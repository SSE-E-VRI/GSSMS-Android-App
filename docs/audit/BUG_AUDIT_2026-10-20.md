# Bug-Finding Audit — 2026-10-20

Scope: full `lib/` codebase, audited in four parallel tracks (auth/network, offline sync, controllers/state, PDF models/services).

Baseline: `flutter analyze` — 144 issues, none errors; `flutter test` — 911 tests passed.
The main vulnerability class is **wrongness under real-world conditions** (races, offline, retries, sign-out), not typical mistakes.

---

## Critical

### C1. `_lastGoodOutbox` resurrects a wiped outbox after sign-out — cross-user data leak
`lib/core/database/local_cache_service.dart:47`
- `clearAllCache()` removes prefs keys but never resets the static in-memory `_lastGoodOutbox`.
- After sign-out, `getOutboxCommands()` with empty persisted value returns **the previous user's outbox** from memory.
- On next login, `refreshPendingSync`/`drainOutbox()` (`sync_manager.dart:231-232`) **writes those commands back to prefs**, undoing the wipe that `clearOperationalSession` documents as a shared-device privacy guarantee.
- Fix: reset `_lastGoodOutbox = const []` inside `clearAllCache()` (and in the corrupt-top-level fallback), or drop the in-memory fallback.
- Note: `test/core/sync/sync_manager_test.dart:131-167` passes only because it uses `InMemoryLocalCacheService` — the test encodes a guarantee the real cache violates.

## High

### H1. 401-retry re-sends an already-finalized `FormData` — multipart uploads permanently fail after token expiry
`lib/core/network/auth_interceptor.dart:131-141, 155`
- `copyWith` carries the original `data`; for multipart (photo uploads) the `FormData` was finalized on the 401 attempt.
- Verified against dio 5.11.0 source: second `finalize()` throws `StateError`, surfaced as "already been finalized" — retry always fails even though refresh succeeded.
- Fix: `if (data is FormData) data = (data as FormData).clone();` before retrying (dio added `FormData.clone()` for exactly this).

### H2. `login`/`loginWithOtp` never check `_opGeneration` — logout racing an in-flight login persists refresh token after sign-out
`lib/features/auth/data/auth_repository.dart:77-99, 188-203` (vs `:303-315`)
- Sequence: login awaits network → concurrent `logout()` bumps generation and clears tokens → login continues and persists the refresh token and repopulates in-memory session. Next app start restores the signed-out user's session.
- `loginWithOtp` in `auth_controller.dart:129-155` also lacks the `_opGenBox` guard every other flow has.
- Fix: capture `final gen = _opGeneration;` at the top; bail out after every `await` if `gen != _opGeneration`.

### H3. Stale request from user A retried with user B's token — cross-identity replay
`lib/core/network/auth_interceptor.dart:107-141`
- Refresh path attaches the **current** token to any 401'd request without comparing identity claims. Background/queued requests issued under user A's expired token get replayed authenticated as user B.
- Also `onSessionExpired` from a stale request can tear down a fresh login's session.
- Fix: compare `user_id` claims of `requestToken` vs `targetAccessToken`; drop the replay when they differ.

### H4. Dedup race — `_enqueueDeduped` check-then-act allows duplicate offline submissions
`lib/features/work_orders/data/work_order_repository.dart:235-253`
- Dedup read runs outside SyncManager `_lock`; double-tap or near-simultaneous submit enqueues two commands with different idempotency keys → server applies twice.
- Fix: atomic read+check+save under the lock (e.g. `enqueueDeduped(cmd, matches:)` on `SyncManager`).

### H5. Online path never sends idempotency keys — lost response double-applies mutation
`work_order_repository.dart:694 (submitLine), 609-615, 786-791, 730-735`
- If the server applies the write but the response is lost (timeout/dropped), the mutation is queued with a **fresh** key → server-side dedup can't match → applied twice.
- `uploadLineAttachment` (`:813-814`) already does it right; mirror that everywhere.

### H6. Dedup on `uploadEvidence` silently drops distinct submissions when `proof_path` is null
`work_order_repository.dart:739-752`
- `null == null` matches two different no-photo evidence submissions → second one never enqueued; user sees "queued" but data is lost.
- Fix: match on `proof_path` only when non-null / include remarks/staff fingerprint.

### H7. Family controllers never disposed — unbounded memory growth
- `work_order_controllers.dart:250, 442`; `verification_workspace_controller.dart:9`; `asset_controllers.dart:300, 32-62`
- All `NotifierProvider.family` / `FutureProvider.family` lack autoDispose; every visited Work Order/Checklist/Asset/Verification Workspace (incl. full audit history, all lines + attachments) is retained for the whole session.
- Fix: make families autoDispose; `ref.keepAlive()` anything intentionally kept.

## Medium

### M1. `_parseDioError`: raw HTML surfaces on login screens; every 502 reported as `EMAIL_DELIVERY_FAILED`
`lib/features/auth/data/auth_api_service.dart:290-292, 312-314, 269-271`
- Gateway HTML error pages are shown verbatim to the user; any 502 during login/verify/reset is misreported as an email-delivery failure. Nested `error` maps stringify as Dart literals instead of using the field parsing.
- Fix: reuse `serverMessage()` from `api_error.dart` (already handles HTML/DRF shapes).

### M2. `getRefreshToken` deletes the token on any read error — transient Keystore failures force logout
`lib/core/storage/secure_storage_service.dart:25-35`
- Bare `catch (_) { delete }` conflates corruption with transient Android post-boot read failures; session irrecoverably destroyed.
- Fix: return null without deleting on read failure; delete only when write/read round-trip confirms breakage.

### M3. `clearOperationalSession` result ignored; one try bounds all 11 invalidates
`lib/core/auth/session_cleanup.dart:32-47`; callers `auth_controller.dart:244, 269`
- A failed SharedPreferences wipe (prior user's data readable on shared device) is silent, per the function's own contract that callers must surface it. A throw in the first invalidate skips the remaining ones.
- Fix: check the returned bool at both call sites; wrap each invalidate individually.

### M4. `fetchAllPages` reports `truncated: false` on early loop breaks
`lib/core/network/paginated_fetch.dart:73-81`
- Malformed/repeating `next` URL breaks the walk but returns complete data — callers present partial data as full, defeating the class's purpose. Fix: return `truncated: true` (or fix the doc).

### M5. JWT with no `exp` treated as forever-valid (fail-open)
`lib/features/auth/domain/models/user_session.dart:120-131`
- Fix: treat missing/unparseable `exp` as `UnauthorizedException` (fail closed).

### M6. No backoff / connectivity gate on drains — retry cap burned while offline
`sync_manager.dart:204-337`; triggers `app.dart:32,54` (every resume), `sync_status_badge.dart:84`
- Every app-resume and every enqueue runs a real HTTP attempt per pending command; 25 app-resumes with no connectivity converts all commands to FAILED.
- Fix: gate `resumePendingSync` on connectivity; add retry backoff.

### M7. `retryCommand`/`retryAllFailed` don't reset `retryCount` — capped command re-fails after one retry
`sync_manager.dart:413-429, 437-453` vs cap check `:289-291`
- "Tap retry" appears broken when tapped offline. Fix: `copyWith(retryCount: 0)`.

### M8. Ordering rule permits `completeRecord`/`transitionStatus` before pending `submitLine` for same record
`sync_manager.dart:128-146`
- `_hasUnsyncedDependency` guards only attachment→line. A record completion can hit the server while its line observations are queued and later fail.
- Fix: block completion/terminal transitions for record X while any `submitLine`/`uploadLineAttachment` for X is unsynced.

### M9. Stale-scope responses overwrite fresh data in Dashboard/Reports/Assets/PendingActions (no sequence guard)
- `dashboard_controller.dart:40-82`; `reports_controller.dart:44-124`; `asset_controllers.dart:199-241`; `pending_actions_controllers.dart:275-321`
- The four main list controllers have `_requestSeq` guards; these four don't. Rapid scope change / pull-to-refresh lets the older response finish last.
- Fix: apply the same `_requestSeq` pattern.

### M10. Work-order detail success paths drop `actions`/`audit` enrichment
`work_order_controllers.dart:310, 355, 383, 420`
- Post-transition `state = WorkOrderDetailLoaded(workOrder: updatedWo)` nulls the enrichment until slow refetch returns — buttons/history blank on slow networks.
- Fix: `copyWith` the existing enrichment; replace only when refetch returns.

### M11. `completeExecution` catch-path reverts to a stale pre-await snapshot
`work_order_controllers.dart:700-706`
- Discards server-confirmed line saves made during the await → "my reading vanished then came back".
- Fix: re-read current `state` in catch (pattern already used in `submitLineObservation:535-563`).

### M12. Filters unchangeable from Error state in most list controllers
- `complaint_controllers.dart:216-231`; `deficiency_controllers.dart:210-258`; `inspection_controllers.dart:242-275`; `asset_controllers.dart:243-268`
- Filter setters are `Loaded`-only; in `Error` state the UI visibly changes but the provider keeps old filters, so retry loads stale filters. Work Orders controller handles this via `previousLoaded` — mirror it.

### M13. Home "attention" section reports success while the dashboard failed to load
`home_screen.dart:654-688`
- `DashboardError` counts as zero attention → green "All up to date" panel on the failure path. Fix: show a neutral warning/retry state on error.

### M14. Checklist PDF silently drops per-line attachment photos the web print shows
`report_pdf/checklist_report_pdf.dart` (photo primitives never used); parsed at `job_work_report.dart:468, 592-595`
- Bytes are preloaded (`job_work_report_repository.dart:59`) but never painted; web mirror (`FormPreview.jsx:127/135/185`) renders the strip. Fix: render attachment strips under checkpoint cells; include in row-height estimates.

### M15. `_Gap` re-inserts full height at top of next page — pagination drift
`checklist_report_pdf.dart:51-86` (verified against pdf-3.11.3 multi_page.dart)
- `apply()`/`clone()` are no-ops, so a gap truncated at a page break consumes its full height again on the next page. Fix: make `_GapContext` stateful (record consumed height).

### M16. Date-only values shift back one day on devices east of IST
`json_parsing.dart:51-57` + `report_date_format.dart:38, 85, 96`
- A bare date (`2026-09-09`) decoded as device-local midnight loses calendar semantics; `webFormatDate`'s `toUtc()+IST` prints `08/09/2026` for Sep 9 on a UTC+6+ device.
- Affected: checklist report date, rectification detectedAt, maintenance register date. `InspectionJobWorkReport` already dodges this via raw string (`:1101-1103`) — extend that approach.

### M17. Several parsers bypass the coercion layer with strict casts
- `asset.dart:151-176` (`id as int?` throws on `3.0`/`"3"`, unreachable `??` fallback); `maintenance_register_entry.dart:116, 119, 130` (raw `jsonDecode` maps may be `Map<dynamic,dynamic>`); `dashboard_models.dart:112` (`as num` cast on `%`).
- One mistyped server field kills the screen — exactly what `json_parsing.dart` exists to prevent. Route everything through `asJsonInt/String/Bool/Double/_map`.

## Low

2. **`WorkOrderPdfService` uses WinAnsi default font, no `pdfSafe`** — `work_order_pdf_service.dart:18-71`; `₹`/Devanagari render blank. Reuse `ReportFonts.load()` + theme.
3. **Complaint/Rectification photo tiles drop captions** — `complaint_report_pdf.dart:280`, `rectification_report_pdf.dart:291` (inspection PDF renders them; web source not in repo — confirm intent).

6. **In-flight outbox command can hit the server after sign-out completes** — `sync_manager.dart:256/269`; epoch guards persistence, not the server write. Consider CancellationToken/epoch check in `_executeCommand`.

9. **Offline cache has no TTL and list/detail disagree after offline mutations** — `local_cache_service.dart:50-76`, `work_order_repository.dart:318-324, 645-655`. Store fetch timestamp; mark queued-mutation entities.
10. **`sync_manager.dart:242-247` attention counts taken pre-eviction and from scoped view** (overlaps 8).

## Verified non-issues (checked, ruled out)
- Refresh coalescing (`AuthRepository._inFlightRefresh` + `QueuedInterceptor`) — no double refresh, no infinite loop.
- Access token not persisted (memory only); only refresh token in EncryptedSharedPreferences.
- RBAC `sessionAllows` fails closed; no bypass found.
- `_requestSeq` guards correct in the four main list controllers.
- `Expando` history caches, `_pendingPassword` cleanup, `ref.listenManual` disposal, postFrame `mounted` checks — all correct.
- Division-by-zero, table row off-by-one, and precedent-suspect expression in PDF code — guarded/evaluated, all correct.
- ReliabilityMetrics key shapes match the backend response.
